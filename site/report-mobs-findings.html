Render-side (docs repo tools/local/render_sprites.py — NOT game-data bugs)

In-game looks are probably fine; the committed docs sprite sheet is what mis-renders. From the

scored look report (top ~20 cards):

  • Palette wrap bug: MobLookColor is applied as palette_index % 33 over the DLPalette blocks.

Colour bytes 11 (pale/albino family: ghost_mantis, albino_buck, ice_panther, pale_scorpion,

stout_pig, boa) and 29 (white family: white_chicken, white_rabbit, white_wolf, shadow_mantis)

render dark/green instead of pale/white. The 5.33 client's colour-byte → palette mapping for

values ≥33 needs real reverse-engineering.

  • Mob5xPalettes.csv override granularity: overrides are keyed per Look only, so

diamond_horse and golden_horse (both look 17, colours 11/30) collapse to the same palette 3.

Needs (Look, Colour) keying or per-mob rows.

  • Look 130 family renders a wrong blob: tiger_blizzard / tiger_slasher / dummy_tiger_slasher

show a small dark shape where the atlas shows the big white yeti-tiger. Verify look 130's frame

index in the 5.33 MONSTER.DNA (possible id shift vs 4.95).

  • 53 mobs unrenderable: look ids ≥617 (abyssal/event/instance content + harvest nodes) exceed

the 5.33 client's monster table — no sprite possible from this client; none are atlas-matched.

Recovery trick worth keeping

NexusAtlas pages deleted since 2005 usually still host their monster GIFs at the predictable URL

https://www.nexusatlas.com/photo/monster60/<lowercase-alphanumeric-name>[1].gif

(100/124 era-mob images recovered that way; Mod_Security blocks bare curl — send browser headers).
