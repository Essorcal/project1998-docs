Test client: bot console, task layer, Frida observe

2026-09-04 · Essorcal

Bot console: every bot on the real map, with stats, timeline and expect results (test client PR #14, issue #12)

  • --console [port] serves a loopback-only dashboard from the CLI process; default port 6174, --console 0 takes any free port and prints the URL.
  • One tab shows every bot on the real 4.x map art with its tile and movement trail, peers, creatures and ground items; a panel per bot with HP, MP, level, experience, gold, bag and equipment; a filtered timeline of the most recent 2,000 stream lines with ok and FAIL distinguished and a count of trimmed lines.
  • The map renderer is the MapEditor's tile decoder compile-linked read-only from the sibling checkout; a change to its public surface in the main repo breaks this repo's build, which the README says.
  • The stream is the existing --json line writer teed to a WebSocket; with the flag off the output path is unchanged and byte-identical. A 5,000-line ring replays to late tabs; each tab's queue is bounded.
  • A dashboard port that is held, duplicate or out of range exits 2 with one line instead of crashing the process. This was the source of the p1998-test.exe crash dialogs.
  • Tile art is decoded on the first browser request, not at startup; patched map cells are outlined; a reconnect draws a run divider and a page that has failed five retries marks itself stale.
  • The CLI now requires the ASP.NET Core 8 shared runtime on every run, with or without the flag (issue #20).
  • Falls back to a labelled grid when the map data or the 5.33 Tile.dat is unavailable.

Hygiene: melee-kill made deterministic, the build kept out of the server checkout, and the #101 rejection probe (test client PR #15, issues #10, #11)

  • melee-kill.txt had two flakes: a 58 percent hit rate over 13 swings at a 6 HP dummy, and HP bleeding across runs until the bot died. Now 28 swings and an @rez at the top; 20 of 20 passes; the header derives the count from the measured rate.
  • Building the test client no longer writes into the referenced server checkout (22 files before, including Shared.dll; 0 of 92 after, also against a stale tree and with a live pair), apart from NuGet's restore state on a never-restored checkout.
  • New script forms: attempt <verb> treats a verb's failure as data; expect disconnected asserts the server closed the socket; an expect on a dropped bot answers text and evidence forms from the look-back and fails state forms on the spot.
  • scripts/pending/rejection-reaches-the-wire.txt settles upstream #101: on a rejected arrival not one byte reaches the wire, 10 of 10, proved server-side by a read-loop trace; on the newer server build the text arrived 2 of 16 times, so the race is real but not deterministic; the login channel never loses its refusal because it writes synchronously and does not close; the GM-kick path delivers it 4 of 6.
  • @mob spawns a level 0, AC 0, 1-damage dummy, so melee numbers against it describe that dummy, not a registry mob.
  • Issues #21 (walk <dir> <n> has no bound) and #22 (cast-heal.txt's @hp 100 rewrites MaxHp) filed.

Task layer, part 1: guards, loops, and navigation by name (test client PR #16, issue #13)

  • Scripts can decide: if ... else ... end, until and while with a mandatory bound, rest until, on death ... end.
  • goto <x> <y> pathfinds on the current map over the server's own .map terrain and object layers and walks it; goto map <id> [<x> <y>] routes across maps through Warps.csv (4,691 rows, 462 maps reachable from Buya) and reports the route.
  • A refused step is re-planned around: a wanderer is retried, a wall is remembered, a level-gated warp quotes what the server said; a goto onto a warp tile is refused before stepping.
  • Four observations added: LevelChanged, Died, Respawned, MoveBlocked; a transition is emitted before the state write that reveals it, because the reverse order is a race a script cannot recover from.
  • Conditions are snapshots and expect still waits; both come from one implementation, so every existing expect count is unchanged.
  • A missing loop bound, a block inside sync, and an out-of-range goto tile are parse errors naming the line.
  • TestClient/Tasks/ holds the map reader, the warp graph, the pathfinder and the navigator, with provenance; ObjectFlagOverrides.csv is read positionally, as the server does, and the note says how many overrides applied.
  • Six new scripts, including two pathfinder falsifications against the real map and a one-way ledge no ground flag can express.
  • Acceptance is now run in both plain and --json modes: a race was invisible in plain text and reproduced 8 of 8 under --json.
  • Issue #24 filed (the no-route message blames the warp rule for an occupant on the approach).

Frida backend F1: attach to the real client and observe (test client PR #23, issue #17)

  • --backend frida attaches to or spawns the real NexusTK 4.95 client and emits the same observations as the wire backend; F1 injects no input, and every input verb is refused with an explicit F2 boundary.
  • Six Winsock exports are tapped through a Python sidecar that validates the client by size and hash and verifies the attached process's path; the traffic is decrypted with the test client's own cipher, so the client's crypt functions are never touched.
  • Every connect to the client's baked-in 127.100.10.1:2000 is rewritten in memory to the selected test server; every other destination, including the game handoff, is left alone. No binary or hosts-file change.
  • Frame assembly, cipher handling, protocol state and typed decoding are shared by both backends through one decoder; the wire backend's sixteen scripts are unchanged in outcome. Plaintext is direction-aware: the client's login opcode is encrypted, the server's reply with the same opcode is not.
  • Raw frames are emitted in both directions; typed observations and state derive from server frames only; player looks are ignored until the entry-only self id is seen.
  • A framing error resyncs one socket direction and no longer disconnects the session; every sidecar precondition failure reaches the CLI as one line naming the reason; a malformed sidecar line is noted and skipped.
  • --timeout-ms governs the wait for a human login; P1998_CLIENT accepts the executable or its directory.
  • Two real-client scripts (scripts/frida/observe-smoke.txt, scripts/frida/yuri-garden-observe.txt) and setup documentation; the eight verified self-walk addresses are recorded by client version for F2.

Tooling (coordination, not in either repo)

  • One server pair per checkout: every concurrent test client worker and reviewer runs its pair from its own run-only server checkout (NexusTK-tc1 to tc4), never from the coordinator's.
  • Reviewers kill processes by path-checked PID only, never by name.

Sprint 5: tick isolation, atomic content reload, a real two-sender sync

2026-09-03 · Essorcal

World.Tick: per-mob AI in MobAiTick.Step, one mob throwing no longer abandons the beat (PR #108, issue #36)

  • The per-mob half of the world tick (buffs, timers, pet, prey, targeting, spellcasting, Sute, chase, retaliation, wander) lives in MobAiTick.Step in Server/World.MobAiTick.cs; World.Tick is the orchestration around it.
  • A creature whose AI step throws is logged with its key, id and map and skipped for that beat; the other creatures, the other maps and every queued packet still go out; the skipped creature is left where the throw found it, nothing is unwound. Before, one throw dropped the whole beat.
  • A map whose AI sweep throws outside any single step is logged and skipped for that beat; the other maps continue.
  • The body moved verbatim: 640 lines, 605 identical, 35 changed in place (26 continue to return, 9 helper prefixes), same order, same Random.Shared draw sequence; tick cost measured unchanged.
  • MobAiTick.Step asserts it runs under the world lock in Debug builds; docs/common/Locking.md lists it with its test.
  • World.MapState is internal instead of private; the tick context does not hand it out.
  • Test seams World.TickOnceForTest (one heartbeat, no thread) and MobTickContextForTest (a per-map context with fresh queues).
  • Six tests in Tests/MobAiTickTests.cs: the poison tick, the blind swing and the walk-home step each queue from a direct-driven step; a step propagates a throw; a step off the lock asserts (Debug); one throwing creature does not cost the others their packets.

Content: one immutable snapshot published with one write (PR #110, issue #33)

  • Content.Load fills a thread-local ContentSnapshotBuilder and publishes one immutable 88-member ContentSnapshot with a single Volatile.Write; every Content.X API is a facade over it, so no call site changed.
  • No window in which a registry and its lookup index disagree: 10 paused reloads and 100,000 reads see 0 mismatches.
  • A failed reload keeps the previous registries, era calendar, door configuration and all four Lua hosts; Reload failed (previous content kept) is now true. Before, a load error could leave a mixed generation live.
  • The era calendar, Doors config and the four Lua hosts (spell_verbs, item_verbs, npc_dialog, mob_ai) prepare candidates during the load and commit at the publish boundary under the Lua gate, after the registry snapshot; reloaded verbs never run against the previous rows.
  • Reload failure tests cover a real data error partway through the load and the final publication boundary; the snapshot member count is derived by reflection.
  • The @reload failure log says the previous content publication remains live; the old "public tables replaced before failure" list is gone; a nested load or a registry write outside a load reports itself as a programming error.
  • On the loading thread, a facade read before its registry is assigned returns the builder's empty default, not the previous load's value; #35 replaces those implicit dependencies with parameters.
  • Migration in eight commits, one per content domain, each building clean; Server/Content.Snapshot.cs is new.
  • Startup load time and heap unchanged (about 205 versus 215 ms medians, 18 MB either way).
  • docs/common/Locking.md: the content publisher now holds the Lua gate; @reload from a GM session takes the gate's slow path.

Test client: a real two-sender sync (Essorcal/project1998-testclient PR #9, issue #7)

  • sync … end and all: build and encrypt every bot's first frame, park it, and release the socket writes together on a barrier from one thread per bot.
  • A block reports the gap it achieved between the writes: sync: released 2 sends on a barrier, gap 3.0 us [two +0.0, main +3.0].
  • New assertion expect gap <us>; a block that cannot be a race says why and fails the assertion instead of passing on an older block's number; a timed-out barrier reports the timeout and fails it too.
  • Measured on the local server: two contending steps now leave a few microseconds apart (median about 3) where they used to leave about 560 apart; two-bots-one-tile.txt now sees the winner vary run to run instead of the first-declared bot winning every time.
  • The winner is not the earlier writer about half the time: at this gap the server's socket read order decides the tile, not the client's write order.
  • New contract member IGameBackend.ArmSendGate, implemented once in GameBackendBase; nothing else in the contract changed shape.
  • New scripts two-bots-all-together.txt and two-bots-nested-all.txt (all: inside sync, the regression guard for a 2 s stall the review found and the round fixed).
  • The barrier's spin rendezvous no longer sleeps, so two writes cannot be split by milliseconds while the gate reports a clean release; the gate is disposed with its block, and the login arrival frame cannot be mistaken for a gated one.
  • README.md and docs/DESIGN.md say what the barrier is worth (independence from what each bot had to do, not the small number on a symmetric block), which frame is gated for verbs like attack <id> that turn first, and that every line of a gated block runs on its own thread.
  • melee-kill.txt is flaky independently of this change (13 swings at a 6 HP mob with a real miss chance); a follow-up.

Tooling (local, not on upstream)

  • worker_guard.py: the coordinator profile now judges git aimed at another clone (git -C <clone> or cd into it) by that clone's own guard mode, so subagents launched from the coordination session are held by the same rules as a desktop session in the clone.
  • worker_guard.py: Windows backslash paths and Git Bash /c/ paths resolve correctly; both shapes previously slipped past the "never another checkout" rule in every profile. Self-test is 68 cases.

Sprint 4: persistence, movement and mob state under the lock, the launcher

2026-09-03 · Essorcal

Character records upgrade explicitly and unreadable rows are protected (PR #96, issue #32)

  • Character saves carry a schema version; a blob with none is schema 0 and reaches schema 1 only through the upgrader.
  • Renaming or removing a character field without an upgrader step fails a test instead of silently dropping player state.
  • An unreadable character record refuses login with its own message, is marked on that failed load, and no save path can overwrite it afterwards.
  • A temporary database error at login says storage is unavailable rather than calling the record corrupt.
  • SQLite migrations run in order under PRAGMA user_version and are idempotent against the deployed schema.
  • Persistence warnings reach the server and login log files, not only the console.
  • Save cost: the never-overwrite check is one integer inside the transaction, not a parse of the stored record.

Two players can no longer land on one tile at once (PR #97, issue #30)

  • The occupancy check and the position write for a step happen inside one world-lock acquisition (World.TryMovePlayer).
  • Walk snap-backs write position through the world lock.
  • The viewport reconcile reads peer positions from a snapshot taken under the lock, so a torn coordinate pair cannot be seen.
  • World.PlayerAt and World.PvpGhostAt removed; their predicates live in TryMovePlayer.
  • New race test: 400 barrier-released rounds, exactly one winner each; the old shape fails 15 to 57 rounds.

Warp arrivals write position under the world lock (PR #102, issue #99, part 1)

  • Every arrival (doorway warps, scripted entrances, world map, Gateway, GM teleports) resolves its tile and writes it inside one lock acquisition (World.PlacePlayer).
  • @approach, @bring and @npc pick their free tile inside the same acquisition that writes it; Session.ApproachTile removed.
  • An ArrivalPolicy switch exists with two members that reproduce current behaviour; whether an occupied arrival tile should refuse or step aside waits on a source check (#99 stays open for that).

Lock hygiene (PR #100)

  • A Lua mob heal and the Lua status read now go through the world lock; the heal's arithmetic is unchanged.
  • The mob-AI lock guard scans MobScript.cs and SuteAi.cs and matches bare, prefixed and member-chain forms.
  • The autosave race test runs a fixed number of barrier-released rounds instead of a wall clock.

Mob state under the world lock, part 2 (PR #105, issue #103)

  • Handing an item to a mob and claiming a harvest node go through lock-owning World methods.
  • The harvest claim is one acquisition; the split form double-claims under a race.
  • The Lua hook entry asserts the world lock is not held (Debug builds).
  • on_healed removed from the mob script hooks: it was advertised, resolved at load, and never fired; which heal would fire it is unsourced.
  • Guard patterns cover the handed list, harvest claim fields, and node-named receivers.

Content.cs split by domain (PR #104, issue #34)

  • Server/Content.cs (5,108 lines) is now Content.cs (496) plus Content.Csv.cs, Content.Maps.cs, Content.Mobs.cs, Content.Items.cs, Content.Spells.cs, Content.Quests.cs, Content.Music.cs, Content.Tuning.cs.
  • Pure file moves, one commit per file; 395 declarations audited identical; loaded content identical before and after.

Dev launcher: Test-Branch.ps1 (PR #98, issue #95)

  • Scripts\Test-Branch.ps1 -Checkout <path> starts a server pair, runs every test client script, stops the pair, prints a per-script table; exit 0 only when all pass.
  • Default port base 3000; refuses when ports are held, when the checkout's own pair is running, or when the server or test client fails to build, each with its own exit code.
  • Ctrl+C and Ctrl+Break stop the pair cleanly; the handler is installed after validation and removed on exit.
  • -Bots grants tester and GM tier to every named account (default botone,bottwo).
  • Scripts\Serve.ps1 fix: its start path returned exit 0 after a failed build; it now returns the build's failure.

Test client PR 4: two bots in one script, melee, and the exchange window (Essorcal/project1998-testclient #4)

  • bot <alias> <user> <pass>, <alias>: prefixes, all:, sync … end; peers tracked through the move packet; attack, trade, offer, confirm, cancel; expect peer, expect hit, expect dead, expect trade, expect exp.

  • Whirlwind and Berserk can now strike other players in PvP areas.
  • Casting mechanics reworked; melee re-measured; item wards now actually apply.

World & content

  • Nagnang added to the world map with its warp corridors opened.
  • New quests: the Dog Linguist and Old Dog dog-spell questlines; trainer secrets are now locked to their home city.
  • Spell rebalance: no-cast maps, buff slots, and post-cast costs.
  • Spawn system overhauled — per-creature respawn times and batched spawn groups.
  • Drinks now play a sip pose.

Social & misc

  • Group join/leave notices now go to the status pane instead of the chat box.
  • Character facing now persists across relog.
  • New GM and Tester command: @rez.
